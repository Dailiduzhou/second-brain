# 支付系统分层设计

支付模块要遵循 Kratos 分层结构，把第三方 SDK、回调协议和业务状态机隔离开。

## 分层职责

| 层 | 职责 |
|----|------|
| `api` | 定义创建支付、查询支付状态等 protobuf 接口 |
| `service` | DTO 转换、调用 Biz、注册 Raw 回调路由 |
| `biz` | 支付用例、状态流转、事务边界、幂等控制 |
| `data` | gopay Client、Adapter、DB Repo、第三方查单 |
| `job` | River 延迟查单、支付成功后的异步副作用 |
| `server` | HTTP/gRPC 路由和 River Worker 生命周期 |

## 依赖方向

```text
service -> biz -> data
service -> raw http callback -> biz
job -> biz
data -> gopay SDK
```

Biz 层不能直接依赖 `gopay`、支付宝或微信 SDK 的类型。支付渠道差异由 Data 层 Adapter 消化。

## Biz 层接口

```go
package biz

import (
    "context"
    "net/http"
)

type PayChannel string

const (
    ChannelAlipay PayChannel = "alipay"
    ChannelWechat PayChannel = "wechat"
)

type PayOrderReq struct {
    OrderNo  string
    Title    string
    Amount   string
    Channel  PayChannel
    ClientIP string
}

type PayOrderResp struct {
    PayPayload string
}

type PaymentRepo interface {
    CreatePayment(ctx context.Context, req *PayOrderReq) (*PayOrderResp, error)
    QueryOrderStatus(ctx context.Context, channel PayChannel, orderNo string) (string, error)
    VerifyNotify(ctx context.Context, channel PayChannel, r *http.Request) (*PaymentNotify, error)
}

type PaymentNotify struct {
    Channel        PayChannel
    OrderNo        string
    ThirdPartyTxID string
    TradeStatus    string
    Amount         string
}
```

金额建议使用字符串或 decimal 类型，避免 `float64` 带来的精度风险。

## Usecase 编排

```go
type PaymentUsecase struct {
    repo    PaymentRepo
    order   OrderRepo
    jobRepo PaymentJobRepo
    tx      Transaction
}
```

Usecase 负责：

- 创建本地支付单。
- 调用支付渠道创建支付。
- 投递延迟查单任务。
- 处理回调和主动查单结果。
- 幂等更新订单状态。
